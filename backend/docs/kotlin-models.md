# Kotlin data models

`@Serializable` data classes for the Android client, matching every
table/view/RPC response shape in `docs/client-contract.md` (current API
surface only -- the legacy functions listed at the bottom of that doc are
intentionally not modeled here). Generated by hand from the live schema
(cross-checked against `types/database.ts`), not a code-gen tool -- keep
both in sync by hand when a migration changes a shape.

Conventions used throughout:

- `kotlinx.serialization.Serializable` + `kotlinx.serialization.SerialName`
  for every snake_case column -- Postgres/PostgREST never produces
  camelCase, so every multi-word field gets an explicit `@SerialName`
  rather than relying on a global naming strategy, so each class is
  correct on its own if copied elsewhere.
- Timestamps (`timestamptz`) are `kotlinx.datetime.Instant` (from
  `org.jetbrains.kotlinx:kotlinx-datetime`); `date` columns are
  `kotlinx.datetime.LocalDate`; `time` columns are
  `kotlinx.datetime.LocalTime`. Add
  `implementation("org.jetbrains.kotlinx:kotlinx-datetime:<version>")`
  alongside `kotlinx-serialization-json` if the app doesn't already have
  it.
- A nullable Postgres column is a nullable Kotlin property with a `null`
  default where the shape is also used for inserts; response-only shapes
  (everything below, since nothing here is ever sent as a request body
  for a plain insert -- all writes go through RPCs with their own
  parameter lists, not raw table inserts) don't need defaults.
- Enums are modeled as Kotlin `enum class` with `@Serializable` and a
  `@SerialName` per constant matching the Postgres label exactly.

## RPC parameter classes

For RPCs with more than one or two parameters, a matching `@Serializable`
request body keeps call sites typed instead of building a raw `JsonObject`
by hand (pass an instance of these to your Supabase Kotlin client's
`rpc(function, parameters = ...)`):

```kotlin
@Serializable
data class CreateServiceRequestParams(
    @SerialName("p_service_id") val serviceId: String,
    @SerialName("p_doctor_id") val doctorId: String?,
    @SerialName("p_slot_start") val slotStart: Instant,
    @SerialName("p_mode") val mode: ServiceMode,
    @SerialName("p_notes") val notes: String?,
    @SerialName("p_contact_phone") val contactPhone: String?,
    @SerialName("p_address") val address: String?,
)

@Serializable
data class TransitionRequestStatusParams(
    @SerialName("p_request_id") val requestId: String,
    @SerialName("p_new_status") val newStatus: RequestStatus,
    @SerialName("p_reason") val reason: String? = null,
)

@Serializable
data class SubmitDoctorProfileParams(
    @SerialName("p_title") val title: String?,
    @SerialName("p_specialization") val specialization: String,
    @SerialName("p_qualifications") val qualifications: String?,
    @SerialName("p_bio") val bio: String?,
    @SerialName("p_years") val years: Int,
    @SerialName("p_license_number") val licenseNumber: String,
    @SerialName("p_modes") val modes: List<ServiceMode>,
    @SerialName("p_slot_duration") val slotDuration: Int,
)

@Serializable
data class SetDoctorAvailabilityWindow(
    @SerialName("day_of_week") val dayOfWeek: Int,
    @SerialName("start_time") val startTime: String, // "HH:MM", sent as plain text inside the jsonb array
    @SerialName("end_time") val endTime: String,
    @SerialName("slot_duration_minutes") val slotDurationMinutes: Int,
)
// set_doctor_availability's single parameter is a jsonb array -- pass
// Json.encodeToJsonElement(windows: List<SetDoctorAvailabilityWindow>)
// as p_windows, not a wrapper object.
```

## A note on `metadata: jsonb` and `status_log: jsonb`

`services.metadata` is a free-form `jsonb` column with no fixed shape
across services -- `Map<String, String>` above is a placeholder; replace
it with whatever shape your catalog actually puts there once services
start using it, or keep it as `kotlinx.serialization.json.JsonElement` if
it genuinely varies per service. `admin_get_request_detail`'s
`status_log` **does** have a fixed, known shape (it's
`request_status_history` rows re-aggregated via `jsonb_agg`), which is why
it's typed as `List<RequestStatusHistoryEntry>` directly above rather than
left as raw JSON.
